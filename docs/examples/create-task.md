# Создание задачи

Операция создаёт одну задачу в состоянии `OPEN` и возвращает её идентификатор.
Контракт Task API 1.0.0. Повтор POST может создать дополнительную задачу.

## Метод и авторизация

`POST /api/v1/tasks`, базовый URL задаётся переменной `BASE_URL`.
Передайте `Authorization: Bearer <токен>` с правом `tasks:write`.
Выдача токена зависит от стенда и не входит в учебный контракт.

## Параметры и тело

Параметров пути и строки запроса нет. Тип тела — `application/json`.
Тело обязательно; неизвестные поля запрещены учебным контрактом.

| Поле | Тип | Обязательно | `null` | Ограничение | Пример |
| --- | --- | --- | --- | --- | --- |
| `title` | string | Да | Нет | 1–120 кодовых единиц UTF-16, не только пробелы | `Подготовить документацию` |

Длина измеряется до обрезки. Пробелы не удаляются автоматически.
Отсутствующий `title`, значение `null` и строка из пробелов приводят к `400`.

## Пример запроса

Команда выполняется в Bash после настройки переменных из [первого запроса](quickstart.md).

```bash
curl --include --fail-with-body \
  --request POST "${BASE_URL}/api/v1/tasks" \
  --header "Authorization: Bearer ${TOKEN}" \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/json, application/problem+json' \
  --data '{"title":"Подготовить документацию"}'
```

## Успешный ответ

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/v1/tasks/42
```

```json
{
  "id": 42,
  "title": "Подготовить документацию",
  "status": "OPEN"
}
```

| Поле | Тип | Обязательно | `null` | Описание |
| --- | --- | --- | --- | --- |
| `id` | integer, int64 | Да | Нет | Положительный идентификатор, выданный сервером |
| `title` | string | Да | Нет | Исходное название, ограничения как в запросе |
| `status` | string | Да | Нет | При создании только `OPEN` |

## Ошибки

Каждый перечисленный ответ имеет `Content-Type: application/problem+json`.

| Статус | Причина | Действие клиента |
| --- | --- | --- |
| `400 Bad Request` | Невалидный JSON, `title` или неизвестное поле | Исправьте тело запроса |
| `401 Unauthorized` | Отсутствует или недействителен токен | Получите токен; ожидайте `WWW-Authenticate: Bearer` |
| `403 Forbidden` | Недостаточно прав | Запросите `tasks:write` |
| `415 Unsupported Media Type` | Тело передано не как JSON | Исправьте заголовок `Content-Type` |

Пример `400` для отсутствующего `title`:

```json
{
  "type": "about:blank",
  "title": "Bad Request",
  "status": 400,
  "detail": "Укажите title длиной от 1 до 120 символов",
  "instance": "/api/v1/tasks"
}
```

`type` задаёт тип проблемы, `title` — название HTTP-статуса, `status` — числовой код.
`detail` помогает исправить запрос, `instance` указывает URI конкретного запроса.
В примере используется путь запроса; корреляционный идентификатор при необходимости задаётся стендом отдельно.
Данные не должны содержать стек исключения или токен.
