# Стайлгайд технической документации REST API

Этот стайлгайд я подготовил в рамках лабораторной работы № 3.
За основу взял документацию учебного Task API на Java и Spring Boot.
В руководстве собрал правила, которые помогают одинаково описывать запросы, ответы и ошибки,
использовать одни и те же термины и сохранять понятную структуру документов.

Я проверил применение правил на двух документах:
[инструкции первого запроса](examples/quickstart.md) и [справочнике создания задачи](examples/create-task.md).
Сайт собрал с помощью MkDocs и настроил автоматические проверки перед публикацией.
Сами правила начинаются с [области применения](guide/scope.md).

## Что входит в проект

- [Ответы по пунктам 1–4](lab/report.md): теория, объект и проектирование правил.
- [Пункт 5](lab/evaluation.md): проверка двух документов и ограничения оценки.
- [Порядок сдачи](lab/delivery.md): ветка, PR и настоящее взаимное ревью.
- [Источники](references.md): учебные материалы и официальные спецификации.

## Границы примера

Task API имеет базовый путь `/api/v1` и учебный контракт версии 1.0.0.
Репозиторий содержит документацию и проверяемые примеры данных. Работающий сервер Spring Boot в него не входит.
Ответы сервера ниже иллюстрируют контракт и не являются результатами сетевых запросов.
