# Проверка и сопровождение

## Q01. Проверки перед PR

Обязательно запустите `npm run lint:md`, `python scripts/check_examples.py` и `mkdocs build --strict`.
Линтер проверяет оформление, строгая сборка - навигацию и внутренние ссылки,
скрипт примеров - JSON и согласованность с учебным OpenAPI.
Эти проверки не подтверждают работу удалённого API и доступность сайта для всех пользователей.

## Q02. Содержательное ревью

Рецензент проверяет задачу читателя, условия, ограничения, примеры и действия при ошибке.
При изменении контракта требуется проверка владельцем API.
Укажите проверку по идентификатору правила: «A02: уточните допустимость null для title».
Ответьте на каждый комментарий исправлением или обоснованием.

## Q03. Версии и изменения

Обязательно меняйте документацию в том же PR, что и соответствующий контракт.
Для существенных правил добавляйте запись в журнал изменений с причиной.
Не удаляйте старую версию API до завершения объявленного периода поддержки.
В этом учебном проекте поддерживается только контракт 1.0.0.

## Q04. Обязанности

Автор отвечает за содержание, рецензент - за независимую проверку, сопровождающий - за слияние и публикацию.
Автоматизация помогает находить ошибки, но одобрение выдаёт человек.
Процесс и команды описаны в корневом `CONTRIBUTING.md`.
Взаимное ревью в лабораторной выполняет другой студент: автоматическая самопроверка его не заменяет.
