# Markdown и оформление

## F01. Заголовки и абзацы

Обязательно используйте ATX-заголовки с `#`, без точки в конце. Не заменяйте заголовки жирным текстом.
Отделяйте заголовки, списки, таблицы и блоки кода пустой строкой.
Рекомендуется ограничивать строку Markdown 120 символами; код и таблицы исключены из лимита.
Сохраняйте UTF-8 и перевод строки LF.

## F02. Код и идентификаторы

Обязательно заключайте поля (`title`), пути (`/api/v1/tasks`) и классы (`ProblemDetail`) в обратные кавычки.
Каждому блоку кода задавайте язык: `bash`, `json`, `http`, `java`, `yaml` или `text`.
Примеры JSON должны разбираться стандартным парсером: без комментариев и завершающих запятых.
Для команд Bash укажите оболочку и условия. Не добавляйте символ приглашения `$` перед командой.

## F03. Списки и таблицы

Нумеруйте шаги процедуры. Для независимых требований используйте маркированный список с `-`.
Таблица обязана иметь строку заголовков; в ячейке должно быть одно сопоставимое значение.
Длинные процедуры выносите из таблиц в текст. Не используйте таблицы для имитации макета страницы.

## F04. Ссылки и изображения

Обязательно используйте осмысленный текст ссылки: «справочник создания задачи».
Внутренние ссылки задавайте относительно текущего Markdown-файла, с расширением `.md`.
Для изображения добавляйте alt-текст с назначением и содержанием. Схему сопровождайте текстовым объяснением.
Не передавайте существенные данные только скриншотом: запрос должен быть доступен для копирования.

## F05. Предупреждения

Перед действием с потерей данных укажите конкретное последствие и способ проверки.
Пример: «Удаление задачи необратимо. Проверьте идентификатор перед отправкой DELETE».
Не маскируйте предупреждение только цветом или пиктограммой.
