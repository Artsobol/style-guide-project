# Сдача и взаимное ревью

## Последовательность работы

1. Опубликуйте основную ветку `main` и включите Pages с источником GitHub Actions.
2. Опубликуйте ветку `docs/accessibility` и откройте PR в `main`.
3. Обменяйтесь ссылками на PR с другим студентом.
4. Прочитайте PR партнёра и оставьте не менее трёх содержательных комментариев.
5. Получите замечания к своему PR, внесите исправления отдельным коммитом и ответьте на комментарии.
6. Дождитесь одобрения, слейте PR и проверьте успешный workflow и опубликованный раздел.

## Что считать содержательным комментарием

Укажите конкретный фрагмент, проблему для читателя и предложение либо вопрос.
Проверяйте полноту условий, согласованность терминов, действия при ошибках и доступность.
Оставляйте замечание только после чтения реального изменения; не копируйте формальные фразы ради количества.

ИИ не выступает в роли второго студента. Не создавайте фиктивные аккаунты, одобрения или комментарии.
Слияние до настоящего ревью не подтверждает выполнение пункта 11.9.

## Подтверждения для преподавателя

- Ссылка на репозиторий, сайт и собственный PR.
- Ссылка на PR партнёра с тремя вашими комментариями.
- Ссылка на замечания партнёра и коммит исправлений.
- Одобрение и merge-коммит.
- Успешный запуск публикации после слияния и страница раздела доступности.

Текущий фактический статус хранится в корневом `STATUS.md`.
